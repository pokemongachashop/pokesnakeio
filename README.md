# 스네이크 아레나 (서버 없는 버전) — 설치·배포·테스트 안내

GitHub Pages + Firebase(Spark 무료 요금제)만으로 동작하는 Snake.io 스타일 실시간 멀티플레이 게임입니다. 별도 게임 서버, 서비스 계정 키, `package.json`이 필요 없습니다.

## 1. 파일 구조

```
(GitHub 저장소 루트)
├─ index.html
├─ style.css
├─ game.js
├─ config.js            ← 사용자가 값을 입력하는 유일한 파일
└─ database.rules.json  ← Firebase 콘솔 "규칙" 탭에 붙여넣을 내용 (사이트 동작에는 필요 없음)
```

## 2. 동작 방식

| 항목 | 누가 처리하나 |
|---|---|
| 내 뱀 이동·부스트 | 내 브라우저가 계산하고, 머리 위치·길이·점수를 초당 8회 RTDB에 기록 |
| 다른 뱀 | 받은 머리 좌표를 이어 붙여 몸통을 복원해 그림. 처음 보는 뱀은 2초마다 저장되는 몸통을 한 번만 읽어 옴 |
| 충돌 | 부딪힌 본인 브라우저가 판정해 스스로 탈락을 기록. 몸통은 먹이로 변함 |
| 먹이 | gameId 시드로 모두가 같은 위치를 계산. 먹을 때 트랜잭션으로 "먼저 먹은 한 명"만 점수 인정 |
| 게임 시간 | Firebase 서버 시각 기준. 누가 나가든 모든 화면이 같은 시각에 끝남 |
| 순위 | 모든 화면이 같은 DB 데이터로 같은 규칙에 따라 계산 |
| 결과 저장 | 종료 2.5초 뒤 가장 먼저 도착한 브라우저가 트랜잭션으로 1회만 저장 |
| 관리자 | 시작·종료·재시작·초기화만 DB에 기록. 게임 루프를 혼자 돌리지 않으므로 새로고침·백그라운드와 무관하게 게임 진행 |

### 백그라운드 규칙 (멈춘 장애물)
- 탭을 숨기거나 휴대폰 화면을 끄면 그 뱀은 **그 자리에 멈춘 장애물**이 됩니다. 다른 사람이 부딪히면 부딪힌 쪽이 탈락하고, 이름 옆에 "자리 비움"이 표시됩니다.
- 돌아오면 1.5초 동안 반투명 보호 상태가 된 뒤 다시 움직입니다. 보호 중에는 부딪혀도 탈락하지 않습니다.
- 네트워크 연결까지 끊긴 상태로 **60초**가 지나면, 남아 있는 다른 참가자 화면이 그 뱀을 탈락 처리합니다. 60초 안에 같은 브라우저로 돌아오면 그대로 이어서 합니다.

## 3. Firebase 설정

### Authentication
1. 빌드 → Authentication → 시작하기
2. 로그인 방법: **익명**, **이메일/비밀번호** 사용 설정
3. 사용자 탭 → 사용자 추가 → 관리자 이메일과 비밀번호 등록. 가상 이메일(예: `admin@snake-arena.game`)도 됩니다. 단, 비밀번호 재설정 메일은 받을 수 없으니 비밀번호를 잘 보관하세요.
4. 등록된 사용자 줄의 **사용자 UID**를 복사해 둡니다.
5. 설정 → 승인된 도메인에 `내아이디.github.io` 추가

### Realtime Database
1. 빌드 → Realtime Database → 데이터베이스 만들기 (잠금 모드로 시작)
2. **규칙** 탭에 `database.rules.json` 내용 전체를 붙여넣고 게시
3. **관리자 등록**: 데이터 탭에서 루트 `+` → 키 `admins` 아래에 키 = 복사한 관리자 UID, 값 = `true` (불리언)로 추가

```
admins
 └─ AbCdEf123...(관리자 UID): true
```

관리자 판별은 이메일 문자열이 아니라 DB 규칙이 `admins/{UID}`를 확인하는 방식입니다. 관리자 계정만 게임 시작·종료·초기화를 쓸 수 있고, 다른 사람이 버튼을 띄워도 DB가 거부합니다. 관리자를 바꾸려면 이 항목만 수정하면 됩니다.

### config.js
프로젝트 설정(톱니바퀴) → 일반 → 내 앱 → 웹 앱(`</>`) 추가 → `firebaseConfig` 값을 `config.js`의 `firebase`에 복사합니다. `adminEmail`은 관리자 로그인 창에 미리 채워지는 값입니다.

`reconnectGraceSeconds`를 바꾸면 `database.rules.json`의 `60000`(밀리초)도 똑같이 바꿔야 합니다. `maxPlayers`는 규칙상 최대 20입니다.

## 4. GitHub Pages 배포
1. 저장소 루트에 파일 4개(`index.html`, `style.css`, `game.js`, `config.js`) 업로드
2. Settings → Pages → Source: Deploy from a branch → `main` / `/ (root)` → Save
3. 1~2분 뒤 `https://내아이디.github.io/저장소이름/` 접속. 이 링크 하나로 PC·모바일 모두 바로 플레이할 수 있습니다.

## 5. 게임 규칙
- 모든 플레이어의 속도·회전 속도는 같습니다. 관리자도 혜택 없음.
- 먹이(가치 1~3)를 먹으면 점수 +가치, 길이 +가치×0.5
- 머리가 다른 뱀의 몸(머리·멈춘 뱀 포함)에 닿으면 탈락합니다. 자기 몸과는 충돌하지 않습니다.
- 원형 벽에 닿으면 탈락이 아니라 중앙 쪽으로 방향이 꺾입니다.
- 부스트: 길이를 초당 2.5씩 써서 빨라지고, 쓴 길이는 꼬리 쪽에 먹이로 떨어집니다. 점수는 줄지 않습니다.
- **공식 순위: 점수 → 현재 길이 → 생존 여부 → 생존 시간 → 먼저 참가한 순**
- 시간이 끝나거나 모두 탈락하면 종료됩니다. 시작 전 3초 카운트다운이 있습니다.
- 진행 중에 참가하면 다른 뱀과 먼 곳에서 시작하고, 1.5초간 보호됩니다. 탈락 후에는 관전합니다.
- 게임 시작 시 연결이 끊긴 대기실 참가자는 자동으로 명단에서 빠집니다. 관리자는 대기실의 "끊긴 참가자 정리" 버튼으로 미리 정리할 수도 있습니다.

조작: PC는 마우스 방향(왼쪽 클릭·스페이스 = 부스트), 방향키/WASD 보조. 모바일은 화면을 끌면 생기는 조이스틱 + 부스트 버튼(또는 두 번째 손가락).

## 6. 보안 한계 (서버 없는 구조의 특성)
- 점수·위치·탈락을 각자 브라우저가 기록하므로, 개발자도구를 다룰 줄 아는 사람은 **점수를 부풀리거나 탈락을 피할 수 있습니다.** 규칙으로 아래만 막습니다.
  - 점수는 한 번 기록할 때 최대 +80, 감소 불가
  - 탈락한 뱀은 같은 게임에서 되살아날 수 없음
  - 남의 뱀 수정 불가 (예외: 60초 이상 연결이 끊긴 뱀의 탈락 처리)
  - 게임 시작·종료는 관리자만 가능
  - 정원(자리 0~19)을 넘는 참가 불가
- 결과가 의심스러우면 Firebase 콘솔 데이터 탭에서 `game/current/heads`를 직접 확인할 수 있습니다.
- 각자 화면에 상대가 0.1~0.2초 늦게 보이므로, 아슬아슬한 충돌은 판정이 엇갈릴 수 있습니다.

## 7. 테스트 방법 (PC 창 2~3개 + 휴대폰)

| 확인 항목 | 방법 | 기대 결과 |
|---|---|---|
| 관리자만 시작 | 시크릿 창으로 참가 | 시작 버튼 없음 |
| 관리자 플레이 | 관리자 로그인 → 참가 → 시작 | 3초 후 관리자 뱀도 똑같이 움직임 |
| 먹이·점수 | 먹이 먹기 | 모든 창 순위표에 1초 안에 반영 |
| 충돌 | 한 창의 머리를 다른 뱀 몸에 박기 | 그 뱀 탈락, 몸이 먹이로 변함 |
| 참가자 새로고침 | 게임 중 F5 | 같은 뱀·점수로 이어서 플레이 |
| 관리자 새로고침 | 게임 중 관리자 창 F5 | 다른 창 시간·움직임 계속, 관리자 뱀 복구 |
| 백그라운드 | 휴대폰 홈 화면으로 나갔다 오기 | 그동안 뱀이 멈춰 있고 다른 창에 "자리 비움" 표시. 복귀 후 1.5초 보호 뒤 움직임 |
| 유예 시간 | 탭을 닫고 30초 뒤 / 70초 뒤 다시 열기 | 30초: 이어서 플레이 / 70초: 탈락 처리되어 관전 |
| 같은 계정 두 탭 | 같은 브라우저 탭 2개 | 새 탭만 조작, 이전 탭은 정지 안내 |
| 정원 초과 | `maxPlayers`를 2로 바꿔 3명 참가 | 3번째는 관전 모드 |
| 종료·결과 | 관리자 [종료] | 모든 창에 같은 결과, `game/history`에 1건 저장 |

## 8. 무료 사용량 (Spark)

무료 요금제로 모든 트래픽을 처리한다고 보장할 수는 없습니다. 콘솔 → Realtime Database → **사용량** 탭에서 꼭 확인하세요.

- **동시 연결 100개**: 브라우저 탭 하나가 연결 하나입니다. 20명이면 충분합니다.
- **다운로드 월 10GB**: 이 구조에서 가장 많이 쓰는 항목입니다. 모두가 모두의 위치를 받기 때문에 사용량이 인원수의 제곱에 비례합니다.
  - 추정치: 20명 × 초당 8회 기준 한 판(5분)에 대략 100MB 안팎(프로토콜 오버헤드 포함 추정). 월 10GB면 대략 수십 판입니다.
  - 10명이면 약 1/4로 줄어듭니다.
  - `config.js`의 `syncRate`를 5로 낮추면 약 40% 절약되지만, 움직임이 조금 덜 부드러워집니다.
- **저장 1GB**: 게임 기록은 판당 수 KB라 문제없습니다.
- 한도를 넘으면 과금되지 않고 그 달 남은 기간 동안 해당 기능이 멈춥니다. 첫 행사 후 사용량 탭의 실제 수치로 판 수를 가늠하세요.
